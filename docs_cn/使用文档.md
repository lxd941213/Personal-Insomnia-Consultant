# 个人失眠顾问 — 使用文档

## 项目简介

**个人失眠顾问**（Personal Insomnia Consultant）是一款移动端优先的 H5 Web 应用，基于 AI 驱动，为用户提供个性化的睡眠健康管理。用户通过填写睡眠档案，即可获得包含风险评估、个性化分析、AI 咨询、睡眠日记、趋势追踪、改善计划在内的全方位睡眠改善方案。

> **重要声明**：本应用定位为**健康管理参考工具**，不构成任何医学诊断。对于高风险情况（如自伤倾向、睡眠呼吸暂停、胸痛等），系统会自动拦截并引导用户寻求专业医疗帮助。

## 快速开始

### 环境要求

- **Node.js**：18+（推荐 20+）
- **npm**：9+
- **AI API Key**：需要 OpenAI 或兼容 API 的密钥

### 安装步骤

```bash
# 1. 克隆项目
git clone <仓库地址>
cd Personal\ Insomnia\ Consultant

# 2. 安装依赖
npm install

# 3. 配置环境变量
cp .env.example .env.local
```

编辑 `.env.local`，填入你的 API 配置：

```env
AI_BASE_URL=https://api.openai.com/v1/chat/completions
AI_API_KEY=你的API密钥
AI_MODEL=gpt-4o-mini
```

> 如果使用国内 API 代理或第三方兼容服务，将 `AI_BASE_URL` 替换为对应端点地址即可。系统会验证必须使用 HTTPS 协议。

### 常用命令

| 命令 | 说明 |
|---|---|
| `npm run dev` | 启动 Vite 开发服务器（含 API 中间件） |
| `npm run build` | TypeScript 类型检查 + Vite 生产构建 |
| `npm run preview` | 预览生产构建产物 |
| `npm test` | 运行所有 Vitest 单元测试（单次执行） |
| `npm run test:watch` | 以 watch 模式运行 Vitest |
| `npm run e2e` | 运行 Playwright 端到端测试 |

> 开发模式下，Vite 通过自定义 `apiDevPlugin` 中间件拦截 `/api/chat` 和 `/api/knowledge` 请求，无需启动 Vercel dev 即可使用 AI 功能。

## 环境变量说明

| 变量名 | 默认值 | 是否必填 | 说明 |
|---|---|---|---|
| `AI_BASE_URL` | `https://api.openai.com/v1/chat/completions` | 否 | AI 提供商的 Chat Completions 端点，必须为 HTTPS |
| `AI_API_KEY` | 无 | **是** | AI 提供商的 API 密钥，缺失时后端会抛出异常 |
| `AI_MODEL` | `gpt-4o-mini` | 否 | 传递给 AI 提供商的模型标识符 |

> 这些变量仅在服务端使用，API 密钥不会暴露到浏览器端。前端通过 `POST /api/chat` 和 `POST /api/knowledge` 请求后端，由后端代理调用 AI 提供商。

## 功能详解

### 一、欢迎页（Entry Page）

用户首次打开应用时看到的页面，包含：

- 星空背景 + 月亮浮动动画
- 应用标题与简介："几分钟内获得个性化睡眠指导"
- "创建睡眠档案"按钮，点击进入档案填写
- 底部健康免责声明

### 二、睡眠档案向导（Profile Wizard）

一个多字段结构化表单，包含以下内容：

| 字段 | 输入类型 | 选项/说明 |
|---|---|---|
| **年龄段** | 下拉选择 | 18 岁以下 / 18-24 / 25-34 / 35-44 / 45-59 / 60+ |
| **性别** | 下拉选择 | 男性 / 女性 / 暂不透露 |
| **就寝时间** | 时间输入 | 如 23:00 |
| **起床时间** | 时间输入 | 如 07:00 |
| **睡眠时长** | 下拉选择 | 4-9 小时左右；填写就寝/起床时间后会自动估算 |
| **主要睡眠困扰** | 下拉选择 | 入睡困难 / 早醒 / 频繁醒来 / 多梦 / 白天嗜睡 / 夜间习惯问题 / 其他 |
| **困扰持续时间** | 下拉选择 | 不到1周 / 1-4周 / 1-3个月 / 3个月以上 |
| **当前压力水平** | 下拉选择 | 较低 / 中等 / 较高 / 很高 |
| **睡眠相关习惯** | 多选标签 | 睡前玩手机 / 午后摄入咖啡因 / 夜间饮酒 / 睡前运动 |
| **情绪状态** | 多选标签 | 焦虑 / 情绪低落 / 烦躁 / 平稳 |
| **运动习惯** | 下拉选择 | 几乎不运动 / 每周1-2次轻运动 / 每周3次以上中等运动 / 经常夜间剧烈运动 |
| **饮食习惯** | 多选标签 | 午后咖啡因 / 夜间饮酒 / 晚餐过晚 / 辛辣高糖 |
| **手机使用习惯** | 下拉选择 | 睡前基本不用 / 睡前偶尔使用 / 睡前1小时内频繁使用 / 醒来后会长时间看手机 |
| **用药情况** | 多选标签 | 未用药 / 偶尔使用助眠产品 / 长期使用助眠药 / 正在服用其他药物 |
| **基础疾病** | 多选标签 | 无 / 慢性病 / 疼痛 / 孕期或产后 / 疑似呼吸暂停 |
| **安全信号** | 多选标签 | 严重症状 / 疑似睡眠呼吸暂停 / 自伤想法 / 药物依赖 / 重大基础疾病 / 孕期或产后 |
| **日间影响** | 文本输入（选填） | 描述睡眠问题对白天的影响 |
| **补充说明** | 文本域（可选） | 任何其他想告诉 AI 的信息 |

提交后，档案会保存到浏览器 `localStorage`，并自动进入应用主界面。当前表单会校验必填字段，但不做医疗诊断或处方建议。

### 三、底部导航（Bottom Tabs）

档案创建后，应用切换为 5 标签底部导航布局：

| 标签 | 图标 | 页面 | 说明 |
|---|---|---|---|
| **首页** | 首页 | TodayPage | 个性化首页仪表盘 |
| **日记** | 书本 | DiaryPage | 睡眠日记记录 |
| **趋势** | 趋势线 | TrendsPage | 睡眠趋势分析 |
| **方案** | 月亮 | PlansPage | 睡眠改善计划 |
| **我的** | 用户 | MyPage | 个人设置与管理 |

### 四、首页（Today Page）

个性化首页仪表盘，包含：

- **时间感知问候**：根据当前时段显示问候语
- **日期显示**与**档案徽章**（就寝-起床时间窗口）
- **评估分数**：如已完成 ISI/PSQI 评估，显示对应分数
- **快速咨询**：展示 9 个场景卡片，点击进入对应场景的 AI 咨询
- **推荐放松**：4-7-8 呼吸、睡眠自测、睡眠知识、身体扫描等快捷入口

当前首页保持轻量入口定位；14 天改善计划和任务状态集中在「方案」页，睡眠记录入口通过底部「日记」标签进入。

### 五、睡眠日记（Diary Page）

分日期记录睡眠数据，支持 7 天日期条切换：

**就寝打卡（Bedtime Check-in）：**
- 心情、压力水平（1-10）、影响因素、计划行动、备注

**起床打卡（Wake Check-in）：**
- 入睡时间、起床时间、入睡耗时（分钟）、夜间醒来次数
- 睡眠质量（1-10）、梦境记录、白天感受、备注

保存后显示 Toast 确认，数据写入 `localStorage`。

### 六、趋势分析（Trends Page）

基于睡眠日记数据的统计分析：

- **近 7 天摘要**：记录天数、平均入睡耗时
- **近 30 天摘要**：记录天数、平均睡眠质量
- **改善执行**：14 天计划任务完成率、连续完成天数
- **任务反馈**：完成任务数、跳过任务数
- **自动洞察**：入睡耗时过长预警、睡眠质量过低预警
- 如尚无睡眠日记，会显示"去记录睡前状态"入口

### 七、改善计划（Plans Page）

三层计划体系：

- **推荐计划**：基于个性化引擎按优先级排序，最多 5 个
- **14 天改善计划时间线**：确定性 14 天任务模板，包含每日任务、依据标签、安全边界、替代动作；高风险用户展示专业评估引导
- **全部方案**：按类别浏览（安全、CBT-I、作息、放松、营养、养生），支持展开/收起分类和方案步骤

### 七点五、14 天睡眠改善计划

应用会根据用户档案、评估结果和安全信号生成本地优先的 14 天计划。普通风险用户会看到 14 天任务时间线，当前日期对应任务标记为 `today`，已存在的任务日志会标记为 `completed` 或 `skipped`。任务带有依据标签，例如 CBT-I、睡眠卫生、放松训练、饮食作息或养生参考。

系统会读取本地 `dailyTaskLogs` 计算完成率、连续完成天数和保守趋势说明；当前版本的计划页主要用于展示计划和执行状态，任务日志由本地存储与趋势模块复用，首页不再直接承载任务反馈表单。

如用户存在自伤想法、疑似睡眠呼吸暂停、胸痛、药物依赖、孕期或产后严重睡眠问题、重度失眠等信号，系统会优先展示专业评估建议，而不是普通改善任务。

### 八、AI 咨询聊天（Chat Page）

核心交互界面，包含以下区域：

**顶部栏**
- 显示场景标签（如从场景入口进入）与评估结果徽章
- 档案摘要（年龄段、主要困扰、睡眠时间窗口）
- "重置档案"按钮，点击后先打开确认抽屉；确认后才清除所有本地数据并回到欢迎页

**消息列表**
- 展示用户消息和 AI 回复的历史记录
- 页面加载时从 `localStorage` 恢复之前的对话
- 聊天记录按场景隔离存储
- 不同咨询场景拥有独立上下文，例如"入睡困难"和"压力焦虑"的历史不会互相混用

**AI 回复卡片**
- 每条 AI 回复以结构化卡片形式呈现，包含以下板块：
  - **总结摘要**：对用户问题的概括性回应
  - **可能因素**：可能导致当前睡眠问题的原因列表
  - **改善建议**：带标题和详细说明的可操作建议
  - **后续问题**：引导用户进一步深入探讨的问题
  - **安全提示**：高风险情况下显示醒目的橙色/红色安全警示
  - **免责声明**：每条回复均附带健康免责声明

**咨询操作区**
- 位于输入栏正上方，按钮顺序为："停止回复"、"重新回复"、"清空记录"
- **停止回复**：在 AI 回复生成中可用，点击后取消当前请求，不再把已停止的 AI 回复写入聊天记录；用户刚发送的消息会保留，便于继续追问或重新回复
- **重新回复**：基于最近一条用户消息重新请求 AI，并移除该消息之后的旧 AI 回复；旧回复不会作为上下文传回模型，避免模型沿用不满意的回答
- **清空记录**：清空当前咨询场景的本地聊天记录，同时把该场景上下文真正写为空；下一次发送消息时，传给 `/api/chat` 的 `history` 为空数组，不只是界面隐藏
- 清空记录只影响当前 `chatScope`，不会删除其他咨询场景、睡眠档案、评估结果、日记、计划或知识缓存

**反馈控件**
- 在首条 AI 回复下方显示"有用"/"没用"按钮
- 反馈记录保存到 `localStorage`，包含消息 ID、反馈值和时间戳

**输入区域**
- 文本输入框 + 发送按钮
- 单条消息限制 4096 字符
- 发送失败时恢复输入内容并提示重试
- 每次发送会附带睡眠档案、最近对话历史、评估结果、当前场景和 14 天计划上下文；后端会先做安全分流，再决定是否调用 AI 提供商

### 九、睡眠评估（Assessment Page）

两个国际通用量表的结构化评估：

**ISI（失眠严重指数）：**
- 7 道题，每题 0-4 分，总分 0-28
- 级别：无失眠（0-7）/ 轻度（8-14）/ 中度（15-21）/ 重度（22-28）

**PSQI-Lite（简化匹兹堡睡眠质量指数）：**
- 6 道题，每题 0-4 分，总分 0-24
- 级别：良好（0-4）/ 一般（5-9）/ 较差（10+）

完成后生成结构化报告，包含分数、级别、摘要、风险标记和下一步建议。评估结果会注入 AI 咨询上下文，影响个性化分析。

### 十、睡眠知识（Knowledge Page）

场景化睡眠知识卡片：

- 场景选择器（9 个睡眠场景）
- 选择场景后先展示本地可信知识卡片，避免必须等待 AI 才能阅读基础内容
- 卡片内容：标题、摘要、关键要点、误区解读（可展开）、可执行建议、安全提示、可继续追问的问题
- "生成 AI 补充参考"按钮可调用 `/api/knowledge` 生成补充内容，失败时最多重试 2 次
- AI 生成结果会写入 `knowledgeCache`，为后续缓存策略保留数据基础
- 所有知识内容都附带健康管理免责声明

### 十一、放松训练（Relaxation Page）

三种引导式放松工具，配有步骤进度和倒计时：

| 工具 | 当前计时时长 | 说明 |
|---|---|---|
| 4-7-8 呼吸法 | 19 秒 | 吸气 4 秒 - 屏息 7 秒 - 呼气 8 秒 |
| 渐进式肌肉放松 | 90 秒 | 双手、肩颈、双腿逐步紧张-放松 |
| 正念引导 | 180 秒 | 观察呼吸、身体接触感，并温和带回注意力 |

支持开始/暂停/完成控制，训练记录保存到 `localStorage`。

当前版本的放松工具仅提供页面内计时和步骤引导，音频内容显示为"即将支持"。

### 十二、我的页面（My Page）

个人设置与管理中心：

- **睡眠档案摘要**：查看已填写的档案信息
- **提醒设置**：就寝/起床提醒开关及时间配置
- **本地数据管理**：重置所有数据，清除后回到欢迎页
- **重置确认**：点击"重置档案"后会弹出底部确认抽屉，列出将被清除的数据；点击"确认重置"才会执行清除，点击遮罩或"取消"不会删除数据

## 个性化引擎

`personalization.ts` 模块基于档案和评估数据，生成 `PersonalizedSleepProfile`：

| 维度 | 说明 |
|---|---|
| **严重程度** | low / mild / moderate / severe — 综合评估分数、安全信号、睡眠时长、困扰时长判定 |
| **就医建议** | 是否应就医、紧急程度（routine / soon / urgent）、原因 |
| **行为目标** | 规律作息、手机边界、咖啡因限制等 |
| **放松目标** | 呼吸法、肌肉放松、正念等（基于压力/情绪） |
| **营养目标** | 褪黑素食物、咖啡因回避、药物交互等 |
| **运动目标** | 规律运动、睡前运动回避等 |
| **中医方向** | 体质辨识（气虚/阴虚/肝郁/痰湿/平和），附带饮食与运动建议 |
| **7 天计划** | 个性化引擎生成的一周任务建议，供 AI 提示词和推荐方案使用 |
| **14 天计划状态** | 独立的 14 天 CBT-I/睡眠卫生任务模板，用于计划页时间线和趋势统计 |
| **安全边界** | 标准免责条款 |

当就医建议为 **urgent** 时，系统完全阻断 AI 生成，直接返回就医引导。

## 安全分流系统（Safety Triage）

应用的核心安全机制，采用**确定性规则**（不依赖 AI 判断）：

**触发条件（满足任一即触发）：**
- 用户消息匹配 10 个高风险正则模式之一：自伤、自杀、停止呼吸、喘息、胸痛、怀孕、产后、每晚依赖安眠药、无法正常生活
- 用户档案中勾选了任何安全信号选项

**触发行为：**
- **不调用 AI 提供商**，直接返回安全降级响应
- 响应包含 `riskLevel: "high_risk"` 和专业就医引导提示
- 以醒目的橙色/红色安全提示卡片呈现，使用 `role="alert"` 确保屏幕阅读器能感知

## AI 响应验证与归一化

每条 AI 回复在返回给前端前都经过严格校验：

- 验证 JSON 结构是否符合预期格式（字段类型、数组存在性等）
- 无效载荷自动降级为安全降级响应（`high_risk`）
- 高风险响应确保 `seekCareNotice` 非空（缺失时填充默认就医提示）
- 每条响应确保 `disclaimer` 非空（缺失时填充默认免责声明）

## 睡眠场景功能

应用提供 9 个可选择的睡眠场景：

| 场景 ID | 中文标签 | 说明 |
|---|---|---|
| `hard_to_fall_asleep` | 入睡困难 | 难以在合理时间内入睡，躺在床上辗转反侧 |
| `poor_sleep_quality` | 睡眠质量差 | 睡眠浅、容易醒、多梦等睡眠质量问题 |
| `stress_anxiety` | 压力焦虑 | 因压力、焦虑等情绪问题导致失眠 |
| `late_night_habit` | 熬夜习惯 | 刷手机、打游戏或工作拖到很晚，想减少熬夜损伤 |
| `wellness_regulation` | 养生调理 | 希望改善整体睡眠质量和健康状态 |
| `bedtime_ritual` | 睡前仪式助手 | 根据用户情况生成专属「睡前 30 分钟计划」 |
| `sound_meditation` | 白噪音 / 冥想音频 | 雨声、海浪、脑波音乐、合规内嵌或外链 |
| `medical_triage` | 在线问诊导流 | 严重失眠用户引导至合规医疗平台 |
| `diet_sleep_link` | 饮食 × 睡眠关联 | 分析用户饮食习惯与睡眠的关系，提供饮食调整建议 |

场景选择器（ScenarioLauncher）以横向滚动或纵向网格形式展示场景卡片，用于首页和知识页面。

进入某个场景后的 AI 咨询会注入该场景的专属提示词和输出规则。模型会优先围绕当前模块回答，例如"睡前仪式助手"会生成睡前 30 分钟分阶段安排，"饮食 × 睡眠关联"会聚焦咖啡因、酒精、晚餐时间等饮食因素，避免所有模块都退化为泛泛的睡眠质量建议。

## 本地数据持久化

| 存储键 | 内容 | 说明 |
|---|---|---|
| `sleepProfile` | 睡眠档案 JSON | 档案填写完成后保存 |
| `chatHistory` | 聊天记录 JSON（按场景隔离） | 每次对话后更新 |
| `feedbackEvents` | 反馈事件 JSON 数组 | 每次反馈后记录 |
| `assessmentResult` | ISI + PSQI-Lite 评估结果 | 完成评估后保存 |
| `knowledgeCache` | 知识卡片缓存（按场景） | AI 生成后缓存，避免重复请求 |
| `sleepDiaryEntries` | 睡眠日记条目 JSON 数组 | 每次打卡后记录 |
| `reminderSettings` | 提醒设置 JSON | 就寝/起床提醒配置 |
| `relaxationSessions` | 放松训练记录 JSON 数组 | 每次训练后记录 |
| `sleepProgram` | 14 天改善计划状态 | 当前计划、天数、状态 |
| `dailyTaskLogs` | 14 天任务打卡记录 | 完成/跳过、睡眠质量、备注等 |

睡眠日记、提醒设置、放松训练、14 天计划和任务日志等可同步记录包含 `id`、`createdAt`、`updatedAt`、`version` 字段；聊天消息和反馈事件使用轻量结构保存。

聊天记录以 `chatHistory` 的分场景对象保存。点击聊天页的"清空记录"会把当前场景对应的数组写为空，保留其他场景历史；点击"重置档案"才会删除所有本地数据。

**内存降级机制**：若 `localStorage` 不可用（如隐私模式、存储已满），自动切换到内存 `Map`，确保当前会话数据仍可正常读写。页面刷新后内存数据会丢失。

## 常见问题

### Q: 启动后聊天没有响应？

检查以下几点：
1. `.env.local` 文件是否存在且 `AI_API_KEY` 已填写
2. `AI_BASE_URL` 是否可从服务器端访问（非浏览器端）
3. 终端日志中是否有 API 调用错误

### Q: 如何更换 AI 模型？

修改 `.env.local` 中的 `AI_MODEL` 值。例如使用 GPT-4o：`AI_MODEL=gpt-4o`。

### Q: 如何使用国内 AI 服务？

将 `AI_BASE_URL` 改为兼容 OpenAI 格式的国内服务端点，同时设置对应的 `AI_API_KEY` 和 `AI_MODEL`。例如：

```env
AI_BASE_URL=https://your-proxy.com/v1/chat/completions
AI_API_KEY=your-key
AI_MODEL=gpt-4o-mini
```

### Q: 数据存储在哪里？安全吗？

睡眠档案、聊天记录、评估结果、日记、反馈、提醒设置、放松训练记录、14 天计划与任务打卡的持久化副本仅保存在浏览器 `localStorage` 中，不会同步到业务服务器。使用 AI 咨询或知识卡片时，前端会把本次请求所需的档案、消息、最近上下文或场景信息发送到后端，由后端调用 AI 提供商。清除浏览器数据，或点击"重置档案"并在确认抽屉中选择"确认重置"，即可删除本地数据。

### Q: 高风险安全提示是如何工作的？

系统在发送用户消息给 AI 之前，会先用 10 个正则表达式进行确定性检测。如果匹配到高风险内容（自伤、呼吸暂停、胸痛等），系统**不会将消息发送给 AI**，而是直接返回就医引导提示。此外，当个性化引擎判定就医紧急度为 urgent 时，也会阻断 AI 生成。这是硬编码的安全网，不依赖 AI 判断。

### Q: 反馈数据会上传吗？

MVP 版本中，"有用/没用"反馈仅保存在本地 `localStorage`，不会上传到服务器。未来版本可能增加服务端汇总分析。

### Q: 支持哪些浏览器？

应用为移动端优先设计，支持所有现代浏览器（Chrome、Safari、Firefox、Edge 的最新两个主要版本）。最大内容宽度 640px，在桌面端居中显示。

### Q: 睡眠评估的结果会影响 AI 对话吗？

是的。完成 ISI + PSQI-Lite 评估后，结果会保存在本地并自动注入 AI 聊天的系统提示词中，使 AI 回复更具针对性。评估结果也会影响个性化引擎的严重程度判定和改善计划推荐。

### Q: 中医体质判断是如何实现的？

基于用户档案中的困扰类型、压力水平、情绪状态和习惯等字段，通过规则匹配判定中医体质类型（气虚、阴虚、肝郁、痰湿、平和或不明确），然后生成对应的饮食与运动建议。这不是医疗诊断，仅作为养生参考。
