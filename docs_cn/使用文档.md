# 个人失眠顾问 — 使用文档

## 项目简介

**个人失眠顾问**（Personal Insomnia Consultant）是一款移动端优先的 H5 Web 应用，基于 AI 驱动，为用户提供个性化的睡眠健康咨询。用户通过填写睡眠档案，即可与 AI 顾问进行对话，获取包含风险分级、原因分析和改善建议的结构化回复。

> **重要声明**：本应用定位为**健康管理参考工具**，不构成任何医学诊断。对于高风险情况（如自伤倾向、睡眠呼吸暂停、胸痛等），系统会自动拦截并引导用户寻求专业医疗帮助。

|---|---|
| 前端框架 | React 19.2.5 |

| 样式 | 纯 CSS，无 CSS 框架 |

## 快速开始

### 环境要求

- **Node.js**：18+（推荐 20+）
- **npm**：9+
- **AI API Key**：需要 OpenAI 或兼容 API 的密钥

### 安装步骤

```bash
# 1. 克隆项目
git clone <仓库地址>
cd Personal\ Insomnia\ Consultant

# 2. 安装依赖
npm install

# 3. 配置环境变量
cp .env.example .env.local
```

编辑 `.env.local`，填入你的 API 配置：

```env
AI_BASE_URL=https://api.openai.com/v1/chat/completions
AI_API_KEY=你的API密钥
AI_MODEL=gpt-4o-mini
```

> 如果使用国内 API 代理或第三方兼容服务，将 `AI_BASE_URL` 替换为对应端点地址即可。系统会验证必须使用 HTTPS 协议。

### 常用命令

| 命令 | 说明 |
|---|---|
| `npm run dev` | 启动 Vite 开发服务器 |
| `npx vercel dev` | 启动 vercel 后端服务器 |
| `npm run build` | TypeScript 类型检查 + Vite 生产构建 |
| `npm run preview` | 预览生产构建产物 |
| `npm test` | 运行所有 Vitest 单元测试（单次执行） |
| `npm run test:watch` | 以 watch 模式运行 Vitest |
| `npm run e2e` | 运行 Playwright 端到端测试 |

## 环境变量说明

| 变量名 | 默认值 | 是否必填 | 说明 |
|---|---|---|---|
| `AI_BASE_URL` | `https://api.openai.com/v1/chat/completions` | 否 | AI 提供商的 Chat Completions 端点，必须为 HTTPS |
| `AI_API_KEY` | 无 | **是** | AI 提供商的 API 密钥，缺失时后端会抛出异常 |
| `AI_MODEL` | `gpt-4o-mini` | 否 | 传递给 AI 提供商的模型标识符 |

> 这些变量仅在服务端使用，API 密钥不会暴露到浏览器端。前端通过 `POST /api/chat` 请求后端，由后端代理调用 AI 提供商。

## 功能详解

### 一、欢迎页（Entry Page）

用户首次打开应用时看到的页面，包含：

- 应用标题与简介："几分钟内获得个性化睡眠指导"
- "创建睡眠档案"按钮，点击进入档案填写
- 底部健康免责声明

### 二、睡眠档案向导（Profile Wizard）

一个多字段结构化表单，共 10 项内容：

| 字段 | 输入类型 | 选项/说明 |
|---|---|---|
| **年龄段** | 下拉选择 | 18 岁以下 / 18-24 / 25-34 / 35-44 / 45-59 / 60+ |
| **就寝时间** | 时间输入 | 如 23:00 |
| **起床时间** | 时间输入 | 如 07:00 |
| **主要睡眠困扰** | 下拉选择 | 入睡困难 / 早醒 / 频繁夜醒 / 多梦 / 白天嗜睡 / 晚间习惯 / 其他 |
| **困扰持续时间** | 下拉选择 | 不到 1 周 / 1-4 周 / 1-3 个月 / 超过 3 个月 |
| **当前压力水平** | 下拉选择 | 低 / 中 / 高 / 非常高 |
| **睡眠相关习惯** | 多选复选框 | 睡前玩手机 / 咖啡因 / 饮酒 / 深夜运动 |
| **安全信号** | 多选复选框 | 严重症状 / 疑似睡眠呼吸暂停 / 自伤想法 / 药物依赖 / 重大基础疾病 / 孕期或产后 |
| **日间影响** | 文本输入 | 描述睡眠问题对白天的影响 |
| **补充说明** | 文本域（可选） | 任何其他想告诉 AI 的信息 |

提交后，档案会保存到浏览器 `localStorage`，并自动进入聊天页面。

### 三、AI 咨询聊天（Chat Page）

这是核心交互界面，包含以下区域：

**顶部栏**
- 显示档案摘要（年龄段、主要困扰、睡眠时间窗口）
- "重置档案"按钮，点击后清除所有本地数据，回到欢迎页

**消息列表**
- 展示用户消息和 AI 回复的历史记录
- 页面加载时从 `localStorage` 恢复之前的对话

**AI 回复卡片**
- 每条 AI 回复以结构化卡片形式呈现，包含以下板块：
  - **总结摘要**：对用户问题的概括性回应
  - **可能因素**：可能导致当前睡眠问题的原因列表
  - **改善建议**：带标题和详细说明的可操作建议
  - **后续问题**：引导用户进一步深入探讨的问题
  - **安全提示**：高风险情况下显示醒目的橙色/红色安全警示
  - **免责声明**：每条回复均附带健康免责声明

**反馈控件**
- 在首条 AI 回复下方显示"有用"/"没用"按钮
- 反馈记录保存到 `localStorage`，包含消息 ID、反馈值和时间戳

**输入区域**
- 文本输入框 + 发送按钮
- 单条消息限制 4096 字符
- 发送失败时恢复输入内容并提示重试

### 四、安全分流系统（Safety Triage）

这是应用的核心安全机制，采用**确定性规则**（不依赖 AI 判断）：

**触发条件（满足任一即触发）：**
- 用户消息匹配 10 个高风险正则模式之一：自伤、自杀、停止呼吸、喘息、胸痛、怀孕、产后、每晚依赖安眠药、无法正常生活
- 用户档案中勾选了任何安全信号选项

**触发行为：**
- **不调用 AI 提供商**，直接返回安全降级响应
- 响应包含 `riskLevel: "high_risk"` 和专业就医引导提示
- 以醒目的橙色/红色安全提示卡片呈现，使用 `role="alert"` 确保屏幕阅读器能感知

### 五、AI 响应验证与归一化

每条 AI 回复在返回给前端前都经过严格校验：

- 验证 JSON 结构是否符合预期格式（字段类型、数组存在性等）
- 无效载荷自动降级为安全降级响应（`high_risk`）
- 高风险响应确保 `seekCareNotice` 非空（缺失时填充默认就医提示）
- 每条响应确保 `disclaimer` 非空（缺失时填充默认免责声明）

### 六、本地数据持久化

| 存储键 | 内容 | 说明 |
|---|---|---|
| `sleepProfile` | 睡眠档案 JSON | 档案填写完成后保存 |
| `chatHistory` | 聊天记录 JSON 数组 | 每次对话后更新 |
| `feedbackEvents` | 反馈事件 JSON 数组 | 每次反馈后记录 |

**内存降级机制**：若 `localStorage` 不可用（如隐私模式、存储已满），自动切换到内存 `Map`，确保当前会话数据仍可正常读写。页面刷新后内存数据会丢失。

## API 接口文档

### POST /api/chat

与 AI 顾问进行对话的核心接口。

**请求体：**

```json
{
  "profile": {
    "ageRange": "25-34",
    "bedtime": "23:00",
    "wakeTime": "07:00",
    "mainConcern": "hard_to_fall_asleep",
    "concernDuration": "1-3 months",
    "stressLevel": "High",
    "habits": ["phone_use", "caffeine"],
    "daytimeImpact": "注意力不集中",
    "safetySignals": [],
    "optionalContext": ""
  },
  "message": "我最近很难入睡，躺在床上要翻来覆去一个多小时",
  "history": [
    {
      "id": "msg_1",
      "role": "user",
      "content": "你好",
      "createdAt": "2026-05-07T10:00:00.000Z"
    },
    {
      "id": "msg_2",
      "role": "assistant",
      "content": "...",
      "createdAt": "2026-05-07T10:00:05.000Z"
    }
  ]
}
```

**请求参数说明：**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `profile` | SleepProfile | 是 | 用户睡眠档案对象 |
| `message` | string | 是 | 用户消息，最长 4096 字符 |
| `history` | ChatMessage[] | 否 | 最近的聊天记录（系统取最后 6 条作为上下文） |

**正常响应（200）：**

```json
{
  "riskLevel": "normal",
  "summary": "入睡困难持续1-3个月，与高压力和睡前习惯有关",
  "possibleFactors": [
    "高压力水平导致交感神经活跃",
    "睡前使用手机抑制褪黑素分泌",
    "咖啡因摄入影响入睡"
  ],
  "suggestions": [
    {
      "title": "建立睡前缓冲期",
      "detail": "睡前1小时停止使用手机，改用阅读或冥想"
    },
    {
      "title": "限制咖啡因",
      "detail": "下午2点后避免咖啡、茶等含咖啡因饮品"
    }
  ],
  "nextQuestions": [
    "你通常几点喝最后一杯咖啡？",
    "睡前使用手机时主要做什么？"
  ],
  "seekCareNotice": null,
  "disclaimer": "本建议仅供参考，不构成医学诊断。如有持续困扰，请咨询专业医生。"
}
```

**高风险降级响应（200）：**

```json
{
  "riskLevel": "high_risk",
  "summary": "检测到可能需要专业关注的情况",
  "possibleFactors": [],
  "suggestions": [],
  "nextQuestions": [],
  "seekCareNotice": "您描述的情况需要专业医疗支持，请尽快联系医疗机构或拨打心理援助热线。",
  "disclaimer": "本建议仅供参考，不构成医学诊断。如有持续困扰，请咨询专业医生。"
}
```

**错误响应：**

| 状态码 | 场景 |
|---|---|
| 400 | 缺少 `profile` 或 `message` 为空 |
| 400 | `message` 超过 4096 字符 |
| 405 | 非 POST 请求方法 |

> 注意：即使 AI 提供商返回异常（JSON 解析失败、网络错误等），API 仍返回 HTTP 200 和安全降级响应，确保前端不会因后端错误而崩溃。

## 数据类型定义

### SleepProfile（睡眠档案）

```typescript
interface SleepProfile {
  ageRange: string;           // 年龄段
  bedtime: string;            // 就寝时间
  wakeTime: string;           // 起床时间
  mainConcern: MainConcern;   // 主要睡眠困扰
  concernDuration: string;    // 困扰持续时间
  stressLevel: string;        // 压力水平
  habits: string[];           // 睡眠相关习惯
  daytimeImpact: string;      // 日间影响描述
  safetySignals: string[];    // 安全信号
  optionalContext: string;    // 补充说明
}
```

### MainConcern（主要困扰类型）

| 值 | 含义 |
|---|---|
| `hard_to_fall_asleep` | 入睡困难 |
| `early_waking` | 早醒 |
| `frequent_waking` | 频繁夜醒 |
| `vivid_dreams` | 多梦 |
| `daytime_sleepiness` | 白天嗜睡 |
| `late_night_habit` | 晚间习惯 |
| `other` | 其他 |

### AiResponse（AI 回复）

```typescript
interface AiResponse {
  riskLevel: RiskLevel;          // 'normal' | 'high_risk'
  summary: string;               // 总结摘要
  possibleFactors: string[];     // 可能因素
  suggestions: Suggestion[];     // 改善建议
  nextQuestions: string[];       // 后续问题
  seekCareNotice: string | null; // 就医提示（高风险时非空）
  disclaimer: string;            // 免责声明
}
```

### ChatMessage（聊天消息）

```typescript
interface ChatMessage {
  id: string;                    // 消息唯一标识
  role: 'user' | 'assistant';   // 消息角色
  content: string;               // 消息文本内容
  response?: AiResponse;         // AI 回复的结构化数据（仅 assistant 消息）
  createdAt: string;             // ISO 时间戳
}
```

### FeedbackEvent（反馈事件）

```typescript
interface FeedbackEvent {
  messageId: string;             // 关联的消息 ID
  value: 'useful' | 'not_useful'; // 反馈值
  createdAt: string;             // ISO 时间戳
}
```

## 部署说明

### Vercel 部署（推荐）

项目采用 Vercel Serverless Function 架构，可直接部署到 Vercel：

1. 将项目推送到 GitHub 仓库
2. 在 Vercel 中导入该仓库
3. 配置环境变量：`AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL`
4. 部署完成

Vercel 会自动识别 `api/` 目录下的 Serverless Function，无需额外配置。

### 其他平台部署

如部署到非 Vercel 平台，需确保：

1. 前端构建产物由 `npm run build` 生成（输出到 `dist/` 目录）
2. `/api/chat` 端点能正确路由到 `api/chat.ts` 的处理逻辑
3. 环境变量 `AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL` 已正确配置

## 常见问题

### Q: 启动后聊天没有响应？

检查以下几点：
1. `.env.local` 文件是否存在且 `AI_API_KEY` 已填写
2. `AI_BASE_URL` 是否可从服务器端访问（非浏览器端）
3. 终端日志中是否有 API 调用错误

### Q: 如何更换 AI 模型？

修改 `.env.local` 中的 `AI_MODEL` 值。例如使用 GPT-4o：`AI_MODEL=gpt-4o`。

### Q: 如何使用国内 AI 服务？

将 `AI_BASE_URL` 改为兼容 OpenAI 格式的国内服务端点，同时设置对应的 `AI_API_KEY` 和 `AI_MODEL`。例如：

```env
AI_BASE_URL=https://your-proxy.com/v1/chat/completions
AI_API_KEY=your-key
AI_MODEL=gpt-4o-mini
```

### Q: 数据存储在哪里？安全吗？

所有用户数据（睡眠档案、聊天记录、反馈）仅存储在浏览器 `localStorage` 中，**不会上传到任何服务器**。清除浏览器数据或点击"重置档案"即可删除所有本地数据。

### Q: 高风险安全提示是如何工作的？

系统在发送用户消息给 AI 之前，会先用 10 个正则表达式进行确定性检测。如果匹配到高风险内容（自伤、呼吸暂停、胸痛等），系统**不会将消息发送给 AI**，而是直接返回就医引导提示。这是一层硬编码的安全网，不依赖 AI 判断。

### Q: 反馈数据会上传吗？

MVP 版本中，"有用/没用"反馈仅保存在本地 `localStorage`，不会上传到服务器。未来版本可能增加服务端汇总分析。

### Q: 支持哪些浏览器？

应用为移动端优先设计，支持所有现代浏览器（Chrome、Safari、Firefox、Edge 的最新两个主要版本）。最大内容宽度 640px，在桌面端居中显示。
